### User 도메인

#### FEAT-USER-010: 본인인증
| 항목 | 내용 |
|------|------|
| **유저 스토리** | 회원으로서, 휴대폰 본인인증을 통해 본인 확인을 완료할 수 있다 |
| **Phase** | MVP |
| **MoSCoW** | Must |

**수용 조건**:
- AC1: Given 회원이 본인인증 페이지에 접근했을 때, When 휴대폰 본인인증(PASS/KCB)을 진행하면, Then 본인인증이 완료되고 인증 상태가 계정에 저장된다
- AC2: Given 본인인증 완료 시, When CI(연계정보)가 저장되어, Then 중복 가입 방지 및 타 서비스 연계에 활용된다
- AC3: Given 본인인증된 계정에서, When 생년월일 기준 19세 이상이면, Then 성인 인증 상태가 자동으로 부여된다

> 기존 FEAT-USER-007(성인 인증) 흡수

#### FEAT-USER-011: 나이인증 (성인 콘텐츠 접근)
| 항목 | 내용 |
|------|------|
| **유저 스토리** | 회원으로서, 성인 인증을 완료하여 19세 이상 콘텐츠에 접근할 수 있다 |
| **Phase** | MVP |
| **MoSCoW** | Must |

**수용 조건**:
- AC1: Given 19세 이상 콘텐츠에 접근 시, When 성인 인증이 완료되지 않은 상태이면, Then "성인 인증이 필요합니다" 안내와 함께 본인인증 페이지로 이동한다
- AC2: Given 본인인증으로 만 19세 이상이 확인되면, When 성인 콘텐츠 접근이 허용되고, Then 성인 작품 필터가 해제된다

> FEAT-USER-010(본인인증)과 연계. 본인인증 시 자동 나이인증

- AC2: Given 자동 저장된 내용이 있을 때, When 같은 회차 작성 페이지에 접근하면, Then "임시저장된 내용을 불러오시겠습니까?" 안내가 표시된다

### Novel 도메인 (추가)

#### FEAT-NOVEL-020: 연재 주기 설정
| 항목 | 내용 |
|------|------|
| **유저 스토리** | 작가로서, 소설의 연재 주기를 설정하여 독자에게 연재 일정을 안내할 수 있다 |
| **Phase** | MVP |
| **MoSCoW** | Must |

**수용 조건**:
- AC1: Given 작가가 소설 설정 페이지에서, When 연재 주기를 선택하면, Then 소설 상세 페이지에 연재 주기가 표시된다
- AC2: Given 연재 주기 옵션은, When 다음 중 선택 가능:
  - **매일 연재**
  - **특정 요일 연재** (월/화/수/목/금/토/일 복수 선택 가능)
  - **주 N회 연재** (1~7회)
  - **격주 연재**
  - **월 N회 연재**
  - **비정기 연재**
- AC3: Given 소설 상세 페이지에서, When 독자가 연재 주기를 확인할 수 있고, Then "매주 월/수/금 연재" 등으로 표시된다
- AC4: Given 연재 주기가 설정된 소설에서, When 연재지연/연재중단 마크 판정 시, Then 설정된 주기를 기준으로 지연 여부를 판단한다 (비정기 연재는 30일 기준)
- AC5: Given 작가가 연재 주기를 변경할 때, When 변경 내역이 기록되고, Then 독자에게 "연재 주기가 변경되었습니다" 알림이 발송된다

> 연재지연/연재중단 마크(FEAT-NOVEL-003)와 연계. 연재 주기 기준으로 마크 판정

### System 도메인 (신규)

#### FEAT-SYS-001: 에러 처리 시스템
| 항목 | 내용 |
|------|------|
| **유저 스토리** | 사용자로서, 오류 발생 시 친절한 안내를 받고 적절한 대응을 할 수 있다 |
| **Phase** | MVP |
| **MoSCoW** | Must |

**수용 조건**:
- AC1: 404 에러 페이지 → "홈으로 가기"/"이전 페이지" 버튼
- AC2: 500 에러 페이지 → "잠시 후 다시 시도해주세요" + 고객센터 링크
- AC3: 네트워크 끊김 → 오프라인 안내, 연결 복구 시 자동 새로고침
- AC4: React Error Boundary → 앱 전체 크래시 없이 해당 영역만 에러 표시
- AC5: 모든 에러 Sentry 자동 기록

#### FEAT-SYS-002: 권한 체크 (RBAC)
| 항목 | 내용 |
|------|------|
| **유저 스토리** | 시스템으로서, 사용자 역할에 따라 접근 권한을 제어할 수 있다 |
| **Phase** | MVP |
| **MoSCoW** | Must |

**수용 조건**:
- AC1: 역할 4단계: Reader / Author / Admin / SuperAdmin
- AC2: 권한 없는 접근 시 403 Forbidden + "접근 권한이 없습니다"
- AC3: 역할별 권한 매트릭스:
  - **Reader**: 소설 열람, 댓글 작성, 코인 충전, 구매
  - **Author**: Reader + 소설 작성, AI 기능, 정산
  - **Admin**: Author + 콘텐츠 관리, 사용자 관리, 공지사항
  - **SuperAdmin**: Admin + 시스템 설정, 정산 승인

### Admin 도메인 (MVP 추가)

#### FEAT-ADM-010: 관리자 마크/배지 부여
| 항목 | 내용 |
|------|------|
| **유저 스토리** | 관리자로서, 이벤트 당첨/우승 등 특별한 사유로 사용자나 소설에 마크/배지를 부여할 수 있다 |
| **Phase** | MVP |
| **MoSCoW** | Must |

**수용 조건**:
- AC1: Given 관리자가 사용자 또는 소설 관리 페이지에서, When 마크/배지 부여 버튼을 클릭하고 마크 종류와 사유를 입력하면, Then 해당 사용자/소설에 마크가 부여되어 프로필/소설 상세에 표시된다
- AC2: Given 마크 종류는, When 다음 등을 포함:
  - **이벤트 당첨** — 이벤트 당첨자 표시
  - **공모전 우승** — 공모전 수상작/수상 작가
  - **추천 작가** — 플랫폼 추천 작가
  - **추천 작품** — 에디터 추천 작품
  - **커스텀 마크** — 관리자가 직접 이름/아이콘 지정
- AC3: Given 마크는, When 만료일을 설정할 수 있고 (영구 또는 기간 지정), Then 만료 시 자동으로 제거된다
- AC4: Given 마크 부여/제거 시, When 사용자에게 알림이 발송되고, Then 부여 이력이 관리자 로그에 기록된다

## AI 줄거리 분석 상세 설계 (Phase 2)

### 토큰 절감 효과
```
기존: 최근 3-5회차 전문 → 100,000+ 토큰
최적화: 최근 3회차 전문 + 이전 회차 요약 → 16,000 토큰 (84% 절감)
```

### 컨텍스트 구성
```
[소설 설정 노트]      3,000 토큰
[캐릭터 설정]         2,000 토큰
[1~10화 요약]         3,000 토큰
[11화 전문]           3,000 토큰
[12화 전문]           3,000 토큰
[13화 - 현재 작성 중]  2,000 토큰
```

### 비용 부담
- 기본 요약(200-500자): **플랫폼 부담**
- 상세 요약(캐릭터/플롯/복선 분석): **작가 토큰 차감**
